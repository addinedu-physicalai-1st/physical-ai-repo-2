01

LLM·STT·TTS 최적화 방법

무거운 LLM·STT·TTS 는 꼭 필요할 때만, 가볍게 돌도록 최적화했습니다.

psychology

LLM — 호출 자체를 줄인다

의도 분류는 규칙 기반 핸들러가 처리해 LLM 호출을 생략(잡담만 LLM). 모델은 메모리에 상주(keep-alive) + 부팅 시 프리로드(warmup)로 콜드스타트를 피하고, 잡담 3b·보고서 7b로 크기를 나눠 응답 길이·컨텍스트를 제한한다.

hearing

STT — 필요한 구간만, 가볍게

faster-whisper 를 GPU면 small·float16 / CPU면 base·int8 로 자동 전환. Silero VAD 로 발화 구간만 잘라 돌려 헛연산을 줄이고, 현재 모드 단어를 힌트로 주입해 짧은 발음도 빠르고 정확히.

campaign

TTS — 첫마디를 빨리

edge-tts neural 로 합성하되, 다 끝나길 기다리지 않고 만들어지는 조각을 즉시 WebRTC 로 흘려보내(스트리밍) 답이 길어도 첫마디가 바로 들리게 한다.

02

STT 오인식을 어떻게 되살리나

받아쓰기는 띄어쓰기·끝음절을 자주 흘립니다("수면실"→"면실"). 이런 변형을 3단계로 흡수합니다.

space_bar

① 공백 제거 후 부분일치

공백을 지우고 비교 → 띄어쓰기 오인식도 잡는다.

blur_on

② bigram Jaccard 유사도

글자 2-그램 유사도로 fuzzy 매칭 → 첫 음절 빠진 발화도 흡수.

spellcheck

③ STT 변형 alias 사전

"놀이반→놀이방", "면실→수면실" 등 자주 틀리는 변형을 교정.

발화무궁화 꽃이 피었습니다 arrow_forward 모드 전환 · 무궁화꽃이 피었습니다공백 제거 후 부분일치
발화충전서 갈거야 arrow_forward 이동 · 충전소alias 교정 + "가" 패턴
03

규칙에 안 걸리면 — 잡담 fallback

어떤 핸들러에도 안 걸리는 말("심심해")은 로컬 LLM(qwen2.5) 으로 넘겨 짧은 대답을 만듭니다. 클라우드 없이 로컬에서 돌려 외부 의존·비용 없이 동작합니다.

shield

LLM 은 느릴 수 있어 2단계 타임아웃 — 기본 프롬프트가 늦으면 짧은 프롬프트로 재시도, 그래도 안 되면 "한 번만 더 말해줄래요?" 안내로 마무리해 대화가 멈춰 보이지 않게 합니다.

child_friendly

응답 스타일도 강제 — 1~3문장·존댓말·외래어 금지, 1인칭 대신 이름("에듀핑이"), 정답형 질문(메뉴·시간)은 사실 먼저 답하고 공감을 덧붙입니다.
