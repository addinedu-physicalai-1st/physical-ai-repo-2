1 2층 구조 — FSM + BT

로봇의 두뇌를 둘로 나눴습니다 — FSM 이 "언제 무슨 모드인가"를, BT 가 "그 모드를 어떻게 수행하나"를 맡습니다. state 하나에 트리 하나.

  • FFSM (robot_fsm.py) — 10 state · 13 trigger 의 순수 상태기계. "지금 어느 모드".
  • BBT (main.py + trees + behaviors) — 그 모드를 실제로 수행하는 트리. 10Hz tick 으로 돌며 FSM 변화에 맞춰 트리를 swap.
layers

뼈대 고정 + leaf 교체. 폴더·상태·트리는 뼈대로 박아두고, 규약을 통일한 leaf(동작)만 각자 추가 → 6명이 코드에서 안 부딪힌다.

의존 방향은 한 방향

fsm → main_trees (상태별 껍데기) → sub_trees (재사용 동작) → behaviors (leaf = 동작 하나) → interfaces (ROS 경계) → rclpy

leaf 는 ROS 를 직접 만지지 않고 interfaces(nav2_client·camera_pan_client·ui_publisher …)를 통해서만 닿습니다.

2 FSM — 언제 무슨 모드인가

10개 모드를 상태기계로 두고 "어떤 상황에 어디로 갈 수 있나"를 표로 선언했습니다. (transitions 라이브러리)

대기 IDLE충전 CHARGING 작업 GOTOFOLLOWLULLABYHIDEANDSEEK 수동 MANUAL복귀 RETURNINGLOW_BATTERY_RETURNING 장애 ERROR
  • 작업 모드끼리 바로 전환 — GOTO·FOLLOW·LULLABY·HIDEANDSEEK 는 IDLE 안 거치고 서로 직접 (트리 swap 1회).
  • 외부는 상태를 직접 못 바꾼다 — UI·Control Server 는 SetGoal.srv 로 요청만 하고, 실제 전이는 FSM 내부 규칙이 판단.
  • 허용 안 한 전이는 조용히 무시 — 잘못된 명령이 와도 엉뚱하게 안 움직임(안전).

03 / 04

3 BT — main 트리 / sub 트리로 나눈 게 핵심

MainTree (상태별 1개)
"이 모드 전체"를 담는 최상위 트리. 모양은 늘 Parallel(monitor + body) — 핵심 동작(body)과 감시(monitor: 배터리·맵경계·HW·사람근접·명령수신)를 매 tick 같이 돌려 "일하면서 동시에 감시". state 10개 = MainTree 10개.
SubTree (재사용 동작 덩어리)
이동·순찰·복귀·자장가·숨바꼭질 같은 실제 행동을 묶은 트리. MainTree 의 body 자리에 꽂힌다. (5종)
MainTree (상태별) = Parallel ├─ monitor leaves (배터리·맵경계·HW· │ 사람근접·명령수신) └─ body = SubTree (재사용 동작)
extension

같은 SubTree 를 여러 state 가 레고처럼 재사용. 이동 SubTree(BT_goto_sub)는 GOTO 뿐 아니라 숨바꼭질의 이동·복귀 단계에서도 그대로 씁니다. → 새 모드는 sub 를 조합만 하면 된다.

10개 MainTree 가 전부 같은 모양이라, 조립은 _shell.py 한 곳에 모으고 state 별 차이(어떤 monitor·어떤 body)는 flag 로만 준다.

04 / 04

4 leaf 설계 — 동작 하나의 규약

leaf = 트리의 잎 = 동작 하나(이동·회전·감시 등). 6명이 각자 추가해도 안 깨지게 규약을 통일했습니다.

  • 1모양·ROS 접근 통일 — 모든 leaf 가 같은 시그니처(name, context)로 시작하고, ROS 는 직접 안 만지고 ctx(인터페이스)로만 호출.
  • 2끝낼 때 뒷정리 — 트리가 갈릴 때 진행 중이던 작업(nav goal 등)을 반드시 cancel → 좀비 동작을 안 남김.

두 종류로 역할 구분

종류하는 일
Monitor
(감시)		계속 지켜보다 이상이 생길 때 1번만 알린다 (배터리·맵경계·사람근접 …).
Action
(행동)		끝나면 SUCCESS · 실패면 FAILURE (이동·회전·도킹 …).
groups

구조가 깔끔해서 협업이 쉽다. 뼈대(폴더·상태·트리)는 고정, 규약 통일된 leaf 만 각자 추가 → 6명이 동시에 작업해도 충돌이 적다.
