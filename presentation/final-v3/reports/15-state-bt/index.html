1 구조 — FSM(언제) + BT(어떻게) 2층

로봇의 두뇌를 둘로 — FSM 이 "언제 무슨 모드인가", BT 가 "그 모드를 어떻게"를 맡습니다. BT 는 py_trees 기반, state 하나에 트리 하나.

  • FFSM (robot_fsm.py) — 10 state · 13 trigger 순수 상태기계. "지금 어느 모드".
  • BBT (main.py + trees + behaviors) — 그 모드를 수행하는 트리. 10Hz tick, FSM 변화에 맞춰 swap.
layers

뼈대 고정 + leaf 교체. 폴더·상태·트리는 박아두고 규약 통일된 leaf 만 각자 추가.

의존 방향은 한 방향

fsm -> main_trees (상태별 껍데기) -> sub_trees (재사용 동작) -> behaviors (leaf = 동작 하나) -> interfaces (ROS 경계) -> rclpy

4 BT 구성 — 왜 main BT + sub BT 로 나눴나

state 하나 = MainTree 하나. MainTree 는 Parallel 로 monitor(항상 감시) ∥ body(모드 동작) 를 동시에 돌리고, body 자리에 SubTree 또는 단일 leaf 를 꽂는다.

MainTree (state 별 1개) = Parallel ├─ monitor 항상 RUNNING · 이상 시 FSM trigger 발화 │ BatteryLow · MapBoundary · HwHealth · Collision · Proximity · CommandListener … └─ body 그 모드의 동작 SubTree (BT_goto_sub · BT_return_sub …) 또는 단일 leaf (FollowTrack · ManualTorqueHold …)

왜 둘로 나눴나

  • ①관심사 분리 — 안전 감시(monitor)와 모드 동작(body)을 한 트리서 병렬. "일하며 동시에 감시".
  • ②재사용 — 한 번 만든 SubTree 를 여러 모드가 그대로 가져다 쓴다. 예: 도킹 복귀 트리는 일반 복귀·배터리 긴급 복귀가 공유, 순찰 트리는 숨바꼭질 안에서 재사용 → 같은 동작을 두 번 안 짠다.
  • ③격리 — 안전 감시와 모드 동작이 따로 돌아서 한쪽 문제가 다른 쪽으로 안 번진다. 예: 모드 동작이 멈춰도 안전 감시(배터리·충돌)는 계속 작동.

SubTree 5종 (body 로 꽂힘)

BT_goto_subvertex 이동 → 도착
BT_return_sub정렬 → 후진 도킹 → docked
BT_hide_and_seek_sub숨바꼭질 단계 (patrol 포함)
BT_lullaby_sub자장가 재생/정지
BT_patrol_subvertex 순회 + 카메라 sweep (재사용)

5 leaf 목록 및 역할 — 공통 · 주행

leaf = BT 의 말단 노드(자식 없는 가장 작은 단위) — 동작 하나 또는 감시/판단 하나를 수행하고 SUCCESS / FAILURE / RUNNING 중 하나를 돌려준다. ROS 는 직접 안 만지고 ctx(interfaces) 경유. 코드상 총 27개(9 카테고리).

common (9) — 횡단 monitor + UI

leaf역할
CommandListenerUI 명령(SetGoal·ForceState·SetRobotPose) → reconcile → FSM trigger
BatteryLowMonitor배터리 ≤15% → battery_low (hysteresis 25%)
BatteryFullMonitor배터리 ≥60% → battery_full (CHARGING→IDLE)
IdleTimeoutMonitor무명령 900s(15분) → idle_timeout
MapBoundaryMonitor로봇 pose 맵 밖 → fault
HardwareHealthMonitorLIDAR/odom staleness(3s) → fault
ProximitySafetyMonitor사람 근접 관측 (반응은 graph_router)
CollisionMonitornav2 collision_monitor 정지 상태 관측
UIPublishUI 이벤트 1회 발행 후 SUCCESS

navigation (6) — 주행 · 도킹

leaf역할
NavigateToVertexgraph_router 액션으로 vertex 주행 (목적지변경·좀비방지)
AlignToDock도크 등진 yaw 로 제자리 회전
ReverseIntoDockN초 후진 (접점센서 없음, 시간기반)
VerifyDockingContact후진 완료=도킹 간주 → docked

BrakeAndWaitcmd_vel=0 + N초 (sweep 전 관성 정리)
