3 학습 최적화를 위해 도입한 추가 요소

카메라 설정

자동 노출을 끄고, 색이 잘 잡히도록 밝기·대비·채도·감마·화이트밸런스를 직접 조정해 고정값으로 사용했습니다.

블럭 집는 방법

  • 집으러 갈 때부터 쌓을 때까지 카메라 화면 정면에 최대한 나오도록 했습니다.
  • 홈포즈에서 올라갈 때 로봇팔을 약 90도로 올리는 동작을 고정했습니다.
  • 블럭 각도가 틀어지면: 상단으로 수직 이동 → wrist 카메라 가로축과 평행하게 그리퍼를 회전 정렬 → 하강해 잡습니다.

04 / 10

4 게임 진행을 원활하게 하기 위한 추가 요소

중단 시 홈포즈 복귀로 위험 최소화

중단 시 모터가 바로 꺼지면 위험하고 사람이 잡아줘야 했습니다. 유치원생을 고려해 중단 시 자동으로 3초간 천천히 홈포즈로 복귀한 후 종료하도록 했습니다. 홈포즈는 시작 시 관절값으로 추출하고, 관절값 편차로 사용자 차례를 인식합니다.

백그라운드 모델 사전 로딩

세션 시작 시 HF 멀티스레딩 제한 + 백그라운드 캐싱을 적용하고, 가위바위보 카드 노출 (4 + 2.5초) 동안 모델 로드를 미리 호출해 게임 지연을 줄였습니다.

실시간 오버레이 연동

로봇 상태(가위바위보 / 추론 / 완료)와 전면 카메라 스트림을 웹 UI에 실시간으로 오버레이합니다.

5 추론 양상 변화

  • 초반특정 위치에서만 잡을 수 있었고, 파란 블럭 전에도 노란 블럭을 잡아버려서 — 사람이 파란 블럭을 먼저 놓은 뒤 추론을 돌려야 했습니다.
  • 5/21 ~파란 블럭을 놓기 전에도 로봇이 움직이지 않고 잘 동작하게 되었습니다.
  • 5/28 ~책상 각도 변경 등 환경 변화로 문제가 재발 → 재학습 대신 ROI 방식으로 해결했습니다 (최종 데모 영상).

06 / 10

6 과정 중 이슈 및 변경

흰색 블럭 잡기 정확도 낮음

추가 녹화·학습을 반복했습니다. 처음부터 큰 스텝으로 돌리기보다 모델 양상을 보고 부족분을 이어 학습하는 방식이 더 효과적이었습니다.

사람 차례에 로봇이 계속 움직임

"집어 놓기 : 안 움직이기"를 약 7:3으로 보강했습니다. 첫 턴은 계속 움직였으나, 비율 집착을 내려놓고 누적 학습하니 빈 구역(첫 턴)도 정지하게 되었습니다.

warning

데모 촬영 중 재발: 책상 각도 변경으로 추론이 흐트러졌습니다 (모방학습의 환경 민감성). 시간상 재학습 대신 다른 방식을 모색했습니다.

해결 — ROI 시작 조건 (HSV + inRange)

front 카메라의 쌓기 구역을 ROI로 잡고, RGB→HSV 변환 후 cv2.inRange로 마스킹합니다. 파란 블럭이 70 % 이상 인식되면 추론을 시작합니다.

07 / 10

7 블럭 쌓기 게임 UI 구성

가위바위보

MediaPipe로 손 모양을 인식합니다. ① 내장 분류기 + ② 랜드마크 기하 분류기(회전·크기 불변)를 confidence 가중 투표하고, margin 확보 시 확정(아니면 재시도)하는 앙상블 구조입니다. 결과로 쌓기 순서를 정합니다.

음성

  • 터치 / 클릭 + 음성 시작 ("노리암, 블럭쌓기 하자")
  • 가위바위보를 외치고 승패를 발화 / 사람 턴 음성 안내 ("파란색 블럭을 쌓아봐")
  • 종료 후 재시작·종료를 음성으로 결정

카드 상태 표시 · 종료 연출

진행 상태를 카드로 안내하고, 로봇이 홈포즈로 돌아오면 사용자 차례로 전환합니다. 그만하기 버튼을 상시 노출하며(음성 종료 가능), 종료 시 칭찬과 팡파레가 나옵니다.
