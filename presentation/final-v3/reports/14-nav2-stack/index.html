1 Nav2 주요 구성요소 — 대부분 그대로 활용 + Route Server 자체 대체

Nav2 는 BT Navigator 가 Behavior Tree 로 독립 모듈들을 오케스트레이션하는 구조. 우리는 Nav2 구성요소를 최대한 그대로 쓰고, 위상 라우팅(Route Server)만 자체 graph_router 로 갈아끼웠다.

※ 주요만 추렸음 — 그 외 Nav2 보조 노드(Smoother·Behavior·Velocity Smoother 등)도 기본값으로 함께 구동.

layers

자율주행 3단계: Route Server(graph_router) 가 지날 vertex 결정 → Planner 가 구간 전역경로(ThetaStar) → Controller 가 추종 cmd_vel(RPP).

2 BT Navigator — NavigateToPose

graph_router 가 경로를 소유 → vertex 마다 제어권을 돌려받아 그 틈에 직접 개입한다. 그 "한 구간 실행" 인터페이스가 NavigateToPose. 결정적 이유는 can_rotate.

BT Navigator navigator 3종단위중간 vertex채택
NavigateToPose단일 목표멈춤 선택 자유 (preempt 로 연속화)✅
NavigateThroughPosespose 리스트안 멈추고 통과 (연속 궤적)✕
FollowWaypoints좌표 리스트매 지점 정지 (task 실행용)✕

결정적 이유 — can_rotate (정지+회전)

좁은 통로에선 안전한 vertex 에서 멈춰 정렬 회전 후 직진해야 한다(뒤로 긴 차체가 곡선으로 돌면 벽 침). 그런데 NavigateThroughPoses 는 중간 vertex 에서 안 멈추고 통과(연속 궤적 설계)라 이 회전을 못 끼운다.

→ 구간마다 제어권을 돌려받는 NavigateToPose 라야 그 틈에 graph_router 가 정지+회전을 넣을 수 있다.

fast_forward

끊김은 preempt 로 해결. 한 구간씩 보내면 vertex 마다 도착=정지→재출발로 cmd_vel 이 끊긴다. → 도착 0.5m 전 다음 goal 을 미리 발사해 nav2 가 자동 교체 → 멈춤 없이 통과. (정지가 필요한 can_rotate·마지막 vertex 만 예외)

check_circle

정리. "안 멈추고 흐르는 구간"은 preempt 로, "멈춰 돌아야 하는 안전 지점"은 can_rotate 로 — 한 구조(NavigateToPose 구간 실행) 안에서 둘 다 해결한다.

3 Vertex · 다익스트라 · can_rotate

Nav2 Route Server(그래프 라우팅)의 개념을 자체 graph_router 로 구현 — 세 가지를 직접 풀었다.

① Vertex — 좌표를 의미있게

원점 기준 (x, y) 숫자가 아니라 "놀이방·수면실·복도" 처럼 이름 붙인 지점(vertex) 으로 공간을 다루고 싶었다.

  • admin·음성·스케줄이 "놀이방으로 가" 한 단어로 수렴 — 좌표 변환 불필요
  • 공간이 바뀌어도 yaml 의 점만 갱신 (코드 변경 0)
  • vertex = 의미 단위 + 사전 검증된 정거장

② 다익스트라 — 거쳐갈 노드 최소화

다익스트라란 — 가중 그래프에서 한 출발점→목표까지 누적 비용이 최소인 경로를 찾는 알고리즘. 출발점에서 가까운(비용 작은) vertex 부터 차례로 확정해 나가 최단 경로를 보장한다.

우린 vertex = 노드, lane = 간선, 비용 = 거리(+방향 전환) 로 두고 출발→목적지 최단 경로(거쳐갈 vertex·거리 최소)를 자동 계산.

현재 위치 TF → 최근접 vertex └─ Dijkstra → vertex 시퀀스 └─ NavigateToPose chain

③ can_rotate — 좁은 길 회전 위험 자체 처리

유치원 실내라 좁은 통로가 많다(가장 좁은 문 0.885m). 구동륜 앞·차체 뒤로 길어, 좁은 길서 제자리 180° 회전 = 차체 후미(0.57m 반경)가 벽을 침 → 위험.

  • 계획 — heading-aware Dijkstra 가 좁은 곳 U턴 경로를 아예 안 만듦 (방향차 135° 초과 전이 거부)
  • 주행 — 넓은 can_rotate 지점에서만 멈춰 정렬 회전 후 직진 (~5.7°, 30°/s, cmd_vel_raw)
insights

Nav2 는 어디가 회전 안전한지 모른다(use_rotate_to_heading=false — 통로 한복판서 회전 시도). 그 판단을 위상 계층(graph_router)이 vertex 단위로 끌어올렸다.

5 Costmap 2D — 좁은 문에 맞춘 inflation

지점은 vertex 로, planner·controller 는 실험으로 정했고 — costmap 은 그 위에서 "문만 통과되게" inflation 만 최소로 맞췄다. (inflation = 벽 주변 비용을 부풀려 떨어져 돌게)

왜 작게 잡았나

가장 좁은 문 0.885m, 차체 폭 0.525m → 문 양옆 여유는 각 ~0.18m 뿐. inflation 을 크게 잡으면 양옆 비용이 문 한가운데서 겹쳐 → 통로가 막힌 것처럼 보여 경로를 못 만든다.

파라미터globallocal왜 이렇게
inflation_radius0.350.10작게 — 좁은 문이 안 막히게 (기본 0.55↓)
cost_scaling_factor4.04.0크게 — 벽 근처만 가파르게 → 벽에 덜 붙음 (기본 3.0↑)
inflation 크게 → 양옆 비용이 가운데서 겹침 → ✕ 막힘 inflation 작게 → 가운데 통과 폭 확보 → ✅ 통과
call_split

벽 가까이 붙여 통과시키되 실제 충돌은 footprint(정확한 차체 모양) 가 막는다. 동적 사람·사물 충돌은 costmap 이 아니라 안전 계층 담당.

6 안전 — Collision Monitor + proximity(사람 경로 우회) + safety_filter

세 안전 장치가 서로 다른 센서로 독립 동작 — 발동 거리는 모두 차체 앞쪽 기준. Collision Monitor·safety_filter 는 cmd_vel 을 막는 반사 정지, proximity 는 사회적 대응.

safety_filter — D435 depth · 앞 0.8m

깊이 카메라 기반 근접 정지 장치. 차체 앞 0.8m 안 장애물 감지 → cmd_vel 0 override. 가장 멀리서 선제 정지. 비대칭 — 전진만 막고 후진·회전은 통과(끼었을 때 탈출). chatter hold 1s.

Collision Monitor — LiDAR · 앞 0.3m

Nav2 표준 라이다 충돌 정지 노드. scan_filtered 로 차체 앞 0.3m 안에 점이 들어오면 즉시 cmd_vel 0. 사물·벽 가리지 않는 최후 하드 정지 — 가장 가까운 마지막 방어선.

proximity — 사람 · 앞 0.6m

사람 전용 경로 대응 장치(person-only). 정면 차체 앞 0.6m 안 사람은 충돌 위험이 아니라 "사람이 길 막음 = 사회적 상황" 으로 보고, graph_router 가 같은 주행 액션 안에서 3분기로 대응:

PAUSE0.6m 안 사람 → goal cancel·정지
RESUME1초 비킴 → 재주행
REROUTE10초 안 비킴 → blocked 등록·재탐색
